Báo cáo — reports surface

Exec dashboard, unified detail reports for clinical and finance, and the Kho ledger. One shared shape across domains, with mode-toggle and cross-tab mechanics. Sketches; translate freely into Tailwind.

Before sketching: four reframes on the brief.

Reframe 1 — Tổng Quan is an attention surface, not a KPI poster. The brief lists 10 candidate KPIs and asks which 6–10 to keep. Wrong question. A morning-read dashboard should answer "do I need to do anything today?" in three seconds. That means the top of the page is a triage row that only shows when something's wrong (the brief's alert row, elevated to primary), and KPIs below are a secondary status check. On a healthy day, the page reads mostly calm — which is itself the signal. A wall of 10 sparklines demands the same attention whether it's a good day or a bad one, so none of them actually get it.

Reframe 2 — persona-row grouping beats priority-mixing. The brief asks which; I'd pick clinical / ops / finance rows without hesitation. The giám đốc reads them in a specific order (is the clinic running? is money flowing? are we behind on anything?), and a row-per-persona lets them scan one row and decide if they need to look further. Priority-mixing assumes everyone's priorities are the same, which they aren't across clinic chains. Rows also mean you can hide an entire persona if a user doesn't have access without the page looking broken.

Reframe 3 — "group-by picker" is really two different controls. The primary dimension is what the chart and table are organized by. The secondary dimension is a cross-tab modifier and fundamentally changes the shape of the output (bar chart → stacked bar, table → matrix). If they're rendered as one unified pill row the user can't tell which one is doing what. I'd split them: primary as a bold "Xem theo" pill group (always one selected), secondary as a smaller optional "× chia theo" chip that appears inactive until toggled on. The × glyph names the operation — this is a cross-tab.

Reframe 4 — "Không (raw rows)" is a different mode, not a group-by option. The brief lists it as one choice among seven for Doanh thu. But "ungrouped" means: no chart, no summary pivot, yes pagination, yes column-level sort, probably different default columns. That's not a group-by value — that's a view mode. I'd separate: Chế độ: Xem tổng hợp / Xem từng dòng toggle, with Xem theo and chia theo only appearing when Xem tổng hợp is active. Collapses the seven-option dropdown to six + a view switch. Also makes the mental model obvious: grouped-and-summarized vs. raw-transactions.

1. Tổng Quan — the morning read

Top of page is the triage row — only renders when it contains items; on a clean morning it collapses to a single-line "Không có cảnh báo nào" and takes up no vertical budget. Below the filter strip sit three persona rows stacked: clinical, ops, finance. Each row has its KPIs at roughly equal weight so the eye scans left-to-right inside a persona without hierarchy questions, then jumps down to the next persona.

Every KPI tile carries four things: label, current value, delta vs. comparison period (with direction and semantic color — but semantic color on the delta only, never the value — a healthy revenue number shouldn't glow green, that's alert fatigue), and a sparkline. The comparison period matches the filter (tháng này → vs. tháng trước; today → vs. hôm qua). Tile-click deep-links to the detail report for that domain, pre-filtered to the same date range and site. Hover reveals the link affordance in the bottom-right corner — not a button, because it'd compete with the number.

One design call worth naming: Ca quá hạn TAT and Vật tư dưới định mức appear in both the triage row (when >0) and their persona row (always). That's intentional. The triage row is "you must act today"; the persona row is "here's the status, for context." Duplicating the number isn't redundant — it's the same value seen through two lenses, the way Điểm sử dụng and Lần sửa are two lenses on the same row in Danh mục.

2. Ca chụp / Ca đọc — the unified detail report

This is the shape that repeats for Doanh thu (mockup 3) and Kho (mockup 4). Worth getting right once.

Two rows under the PageHeader carry the whole mechanic. The first row is the FilterBar — date range, site, modality, loaded with the selection state visible so you can tell at a glance what you're looking at. The second row is the dimension bar, and this is where Reframe 3 lives: Xem theo is a pill group with exactly one selected (primary dimension, determines the chart), and × chia theo is a smaller chip that starts inactive. Toggle it on and you get a secondary dimension picker + the chart switches from bar to stacked bar. The × prefix names the operation literally: this is a cross-tab.

Below the dimension bar, a four-number summary strip (Ca, TAT p50, TAT p95, % đúng hạn) that doesn't change shape regardless of grouping — it's always the summary for the filtered result. The chart renders the primary dimension; labels are bars (horizontal, which reads better when the dimension has 6+ values like doctor names). The table below has dimension-driven columns: grouping by Máy shows Máy / Ca / TAT p50 / TAT p95 / % đúng hạn, grouping by BS đọc shows BS / Ca đọc / TAT trung bình / % đúng hạn. Row-click drills into /ris with the row's value pre-applied as a filter, scoped to the same date range.

One thing the mockup shows that's easy to miss: when × chia theo is active, the chart legend appears and the table becomes a matrix (dimension × secondary), not a flat list. The sketch here is primary-only for legibility; the stacked variant is described in prose below rather than drawn, since it's the same layout with a pattern swap.

3. Doanh thu — the same shape, view-mode split

Reuse is the design: filter bar → dimension bar → summary strip → chart → table. Status filter replaces modality filter (all / paid / refunded / e-invoiced), and the dimension options shift to revenue-relevant ones. Everything else is the same component.

The one genuinely new mechanic is Reframe 4 — the Chế độ toggle. Two states: Xem tổng hợp (default) → grouped, charted, summarized; same layout as the clinical report. The Xem theo pill group appears. Xem từng dòng → raw rows, no chart, no grouping. Summary strip stays (still shows the overall totals, which is useful). Table becomes a paginated ledger with sortable columns and a page readout. The Xem theo pill group hides because it doesn't apply.

The mockup below shows Xem tổng hợp active, grouped by Chi nhánh — this is the most common use (weekly finance review). Row-click drills into Phiếu thu filtered to the grouped value. I've kept the secondary × chia theo chip visible but inactive; toggling it on for Chi nhánh × Loại dịch vụ turns the chart into a stacked bar and the table into a small matrix, same mechanic as clinical.

One thing the finance mockup shows that clinical doesn't: the summary strip here carries a Nợ (outstanding receivables) tile, which is a count-and-amount rather than a rate — it's a link to the consume-points-style drill-down showing which invoices are actually unpaid. Clinical's equivalent would be "ca quá hạn TAT" but that already has its own alert in Tổng Quan, so it's not duplicated in the summary.

4. Kho — two reports, shared shape

The two Kho reports the brief asks for — Tiêu thụ vật tư and Sổ kho — map cleanly onto the same unified shape with small variations. I'll describe both, then sketch the more interesting one.

Tiêu thụ vật tư is a straight reuse of the clinical/finance shape: filter (date, site, category), Xem theo [Vật tư] [Nhóm vật tư] [Chi nhánh] [Dịch vụ], summary strip (tổng tiêu thụ / giá trị / biến động vs. tháng trước / biên lỗi auto-deduct), bar chart, table. Nothing genuinely new.

Sổ kho is more interesting because it inherits Reframe 4 from finance. Its natural mode is Xem từng dòng — a transaction ledger showing nhập/xuất/điều chuyển/điều chỉnh/auto-deduct line by line, paginated, filterable by transaction type. But you also want an aggregate view ("tổng nhập tháng này theo loại giao dịch") which is Xem tổng hợp grouped by loại giao dịch. Same toggle, same behavior.

I'm sketching Sổ kho in ledger mode below. The key design choices: transaction-type chips serve as a filter (the row of pill filters with counts), each row carries a type indicator (color-coded bullet + 3-char code), the quantity delta shows with sign (+50 for nhập, −3 for xuất), and the rolling balance on the right anchors everything. No chart in this mode — the ledger is the chart; adding a bar graph of volume-by-day would compete with the table without adding information the user isn't already extracting by scanning.

One pattern worth naming: the ledger is the unified transaction log from the warehouse module, filtered to reporting mode. Same record shape, different chrome (filter bar + summary strip above instead of inventory-workspace chrome). This means admins auditing "why did Hà Nội run out of contrast on 15/04" in the warehouse log get the same view they'd see here in Sổ kho — just from a different entry point. That reuse is deliberate; makes this report trivial to build because the data layer already exists.

5. Shared mechanics worth naming

Three components carry the weight across these four mockups. The FilterBar + dimension bar is the two-row header that everything below responds to — keeping them as separate visual strips (not collapsed into one long row) lets the user scan scope and organization as two separate thoughts. The Chế độ view-mode toggle (Reframe 4) only shows on reports where raw-row view makes sense, which is Doanh thu and Sổ kho — clinical and consumption reports don't need it because "ungrouped ca chụp" isn't a useful mental model. The row-click drill-down is consistent: every row is a link into the transactional workspace for that domain (Ca chụp → /ris, Doanh thu → /phieu-thu, Sổ kho → /quan-ly-kho) with the row's dimension and the report's date range pre-applied.

6. Secondary dimension — the stacked variant

The × chia theo chip is inactive in all four sketches. When toggled on, three things change: (1) a secondary-dimension picker appears next to the chip (same pill row as the primary); (2) the chart shifts from flat bar to stacked bar with a legend showing the secondary values and an accompanying pattern/hatch cue for each stack — color alone isn't accessible; (3) the table becomes a small matrix with secondary-dimension columns. The user can clear the cross-tab by toggling the chip off, which collapses back to the flat primary. I didn't draw it because it's the same layout with predictable changes — but it's worth prototyping early, because the table-as-matrix case has real width constraints (if you cross-tab Chi nhánh × Dịch vụ with 4 × 380 = 1520 cells, you need column virtualization or top-N truncation).

7. Keyboard wiring

/ focuses the first filter in the FilterBar (date range); once inside, Tab walks through filters and Esc closes an open picker. g cycles the Xem theo primary dimension in the order shown left-to-right — this is the killer shortcut for a giám đốc exploring a report, because it lets you re-organize without touching the mouse. e triggers CSV export. On tables, j/k move the row cursor; Enter drills. These match the conventions from Danh mục and Quản lý kho so the user learns them once.

8. States to think about before build

Empty filter result — "Không có dữ liệu cho bộ lọc hiện tại" with a Xóa bộ lọc link, not an illustration. Cheaper to re-filter than to explain why there's nothing.

Large-result Xem từng dòng — the Sổ kho pagination on mockup 4 is "1–9 / 2.047" which is honest. Server-side pagination is mandatory; sorting too. Don't try to load 2k rows client-side and filter — the date filter is the real bound.

Stale data — every mockup carries "dữ liệu cập nhật 09:42 hôm nay" somewhere subtle (Tổng Quan has it on the second chart card). Reports aren't real-time — they run off a nightly or hourly aggregate, and surfacing that honestly prevents "why doesn't this match the live workspace?" support tickets.

Loading — skeleton rows in the table, skeleton bars in the chart (bars of varying lengths in a tertiary-gray fill). Never block the filter bar — the user might be adjusting filters while data loads.

Permission scoping — if a user doesn't have access to a persona's data, the corresponding row in Tổng Quan doesn't render at all (not "Bạn không có quyền") and the sidebar hides the persona. Silent scoping reads more gracefully than visible locks.

9. What I didn't draw

The three persona-specific Tổng quan pages (Lâm sàng / Vận hành / Tài chính) — the brief says they already exist as /dashboard/{clinical,ops,finance}, just wrapped in new chrome. I didn't draw the Tiêu thụ vật tư Kho report because it's the finance-report shape with a different filter set and column list; sketching it would just be a palette swap. I didn't draw the stacked bar variant when × chia theo is on, or the Xem từng dòng finance view — both are described in prose and are predictable derivations of what's drawn.

The next thing I'd prototype is the cross-report consistency — put Ca chụp, Doanh thu, and Tiêu thụ vật tư on the same screen side-by-side to check that a giám đốc going from Ca chụp to Doanh thu feels like the same report with a different filter, not a different product. The unified shape only pays off if that feels true in interaction, not just in screenshots.
